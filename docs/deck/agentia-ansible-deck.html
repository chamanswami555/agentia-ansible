The problem

One change ticket, one automated run, and a Salesforce step still done by hand

  • A Salesforce change rarely ships alone: the same ticket carries a database migration, an infrastructure change, a feature flag. Platform teams already run those from Ansible Automation Platform: inventories, approval nodes, schedules, RBAC, a job history that doubles as evidence.
  • Copado releases sit outside that: someone presses Submit, waits for jobs, pastes screenshots into the change ticket.
  • Validation, smoke tests, approval and deployment are four manual steps. A failed job at night waits until morning.

Agentia Headless changes the input

Every step is now a CLI command with JSON output.

But a CLI is not a building block

Each team would still write its own polling, parsing, error handling and approval logic.

The release window

Validate, prove, approve, ship, with evidence at every step

1. Health checkCopado governance checks before anything moves.
2. ValidateEach story: work submit, wait for the promote job, then for the check-only deployment the promotion record names.
3. Smoke suiteRobotic Testing run, optional.
4. Approval gateA typed yes, or approve: true from an AWX node, MCP or CI. A plain pause is skipped without a terminal; this one fails closed.
5. Copado Submitwork submit --done per story: promote job, deployment job, both waited for. Or merge_and_deploy on an existing promotion.
6. Evidencevalidations, deployment, health checks before and after, as JSON with transaction ids.

Nightly validation runs steps 1 to 3 for every story in flight and fails loudly. Remediation reads a failed job and its log, asks Copado AI for a diagnosis, writes an incident, and can resume the job.

Event-Driven Ansible, MCP and the skill

Nobody watches a console; nobody deploys without a decision

A job fails at 02:00

The source sees the status change, the rule fires, the remediation playbook reads the job and its log, asks Copado AI for a diagnosis, writes the incident file, and resumes the job if the team allows it. Proved end to end offline and live.

An agent asks for a release

Why not just...

The questions we asked ourselves first

ObjectionAnswer
Call the CLI from a shell task?No change reporting, no dry run, and polling, parsing, pagination and errors rewritten in every playbook. The modules are the tested layer.
Use Copado's own automations?They run inside Copado. The change window spans Salesforce, databases, infrastructure and flags, and runs from Ansible with its approvals, RBAC and schedules.
Use a CI pipeline?You can; our CI does. Ansible adds approval nodes, inventories, credentials, schedules and event-driven remediation.
Use the Agentia MCP server?194 raw tools versus five governed workflows with an approval gate and an evidence folder.
What does it not do?No rollback (the CLI has none), no Windows control node, Robotic Testing and Copado AI verified against recorded answers only. Listed, not hidden.
